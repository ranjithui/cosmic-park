============================================================
 COSMIC PARK — HOW TO RUN
 Website (React) + Booking API
============================================================

You need TWO things running at the same time:

  1. The booking API   -> http://localhost:4000
  2. The website        -> http://localhost:5173

Start the API FIRST, then the website. The website talks to the
API through a dev proxy, so the API must already be up.

Requirements: Node.js 18+ and npm (check with:  node -v ).
Also needed: a running PostgreSQL database.

To put the site online for a demo instead of running it
locally, skip to "RUN IT LIVE" at the bottom.

For the admin dashboard login, see "ADMIN LOGIN" at the bottom.


------------------------------------------------------------
 STEP 1 — START THE BOOKING API  (port 4000)
------------------------------------------------------------

Folder:  apps\api

The API uses Prisma + PostgreSQL. You need a running PostgreSQL
database and a connection string.

  1. Open a terminal in the API folder:
       cd "C:\Users\USER\ui ux\cosmic-park\apps\api"

  2. Create the .env file (first time only):
       copy .env.example .env
     Then edit .env and set:
       - DATABASE_URL   -> your PostgreSQL connection string
       - JWT_SECRET     -> any long random string

  3. Install, set up the database, seed sample data (first time only):
       npm install
       npx prisma generate
       npx prisma migrate deploy
       npm run seed

     "migrate deploy" applies the migration already committed in
     prisma\migrations\. Use "npx prisma migrate dev" only when you
     have CHANGED schema.prisma and need a new migration.

  4. Start the API:
       npm run dev

     You should see:
       Cosmic Park booking API listening on http://localhost:4000

  Seeded admin login:  admin@cosmicpark.in / ChangeMe123!
  Admin dashboard:     http://localhost:4000/admin

  To use a different password, set ADMIN_PASSWORD in .env and
  re-run "npm run seed". While that variable is set, each seed
  run resets the login to it.

  The seed is safe to re-run. It matches existing records by
  email / slug / name and updates them in place, and it never
  deletes anything, so test bookings you have made survive it.

  NOTE: The "DB_PROVIDER=sqlite" shortcut in the API README does
  NOT work as written (Prisma rejects env() in the provider, and
  SQLite doesn't support the schema's enums). Use PostgreSQL.


------------------------------------------------------------
 STEP 2 — START THE WEBSITE  (port 5173)
------------------------------------------------------------

Folder:  apps\web

  1. Open a SECOND terminal here:
       cd "C:\Users\USER\ui ux\cosmic-park\apps\web"

  2. Install dependencies (first time only):
       npm install

  3. Start the website:
       npm run dev

  4. Open in your browser:
       http://localhost:5173

  Leave both terminals open while you use the site.


------------------------------------------------------------
 SHORTCUT — FROM THE PROJECT ROOT
------------------------------------------------------------

The root package.json wraps the commands above, so you don't
have to cd into each folder:

  cd "C:\Users\USER\ui ux\cosmic-park"

  npm run install:all    -> installs BOTH apps (first time only)
  npm run seed           -> seeds the database (safe to re-run)

  npm run dev:api        -> terminal 1: starts the API
  npm run dev:web        -> terminal 2: starts the website

  npm run build:web      -> production build into apps\web\dist

You still need the apps\api\.env file and the Prisma steps from
Step 1 before the API will start.


------------------------------------------------------------
 TRY THE BOOKING FLOW
------------------------------------------------------------

  - Home page: click "Check availability" or use the search bar.
  - Pick dates that fall inside a seeded rate plan to see tier
    pricing, e.g. a Festive stay:
       Check-in:  2026-12-26
       Check-out: 2026-12-29
  - Step through: Dates -> Choose stay -> Guest details + add-ons
    -> Payment -> Confirmation.
  - Payment is a DEMO (no real gateway / no card charged); it
    confirms the booking against the API so you can see the full
    flow end to end.


------------------------------------------------------------
 PRODUCTION BUILD (optional)
------------------------------------------------------------

  In apps\web:

  npm run build      -> outputs the site to  dist\
  npm run preview    -> serves the built site locally

  Pointing at a deployed API instead of localhost:
    Copy .env.example to .env and set:
      VITE_API_BASE_URL=https://your-api-domain
    (Leave it blank for local dev — the proxy handles it.)

  This value is baked in when you BUILD, not when you start the
  server. Change it and you must run "npm run build" again.


------------------------------------------------------------
 RUN IT LIVE (hosted demo)
------------------------------------------------------------

The project is set up to deploy to Render — the API needs a
real always-on server (it runs a background job to release
expired holds, and writes uploads to disk), which is why it is
not on a serverless host.

  render.yaml   -> the blueprint: database + API + website
  DEPLOY.md     -> step-by-step instructions and free-tier limits

Short version:
  1. Push the repo to GitHub.
  2. Render Dashboard -> New -> Blueprint -> pick this repo -> Apply.

  That's the whole setup. The blueprint creates the database,
  applies migrations, seeds the demo data, generates the JWT
  secret, and points the website at the API on its own.

  Use "New -> Blueprint", NOT "New -> Web Service". The Web
  Service form ignores render.yaml and configures nothing.

The live demo (deployed 10-08-2026):

  Website  ->  https://cosmic-park-web.onrender.com
  API      ->  https://cosmic-park-api.onrender.com
  Admin    ->  https://cosmic-park-api.onrender.com/admin
  Health   ->  https://cosmic-park-api.onrender.com/api/health

Before showing the demo: open the Health URL first and wait for
it to respond. On Render's free plan the API sleeps after 15
minutes idle and takes 30-60 seconds to wake, and the website
will look frozen while it does.

------------------------------------------------------------
 TROUBLESHOOTING
------------------------------------------------------------

  - Blank prices / "Could not reach the booking service":
      The API isn't running. Start it (Step 1) on port 4000.

  - "No availability for these dates":
      Those dates are already booked/blocked, or fall outside a
      seeded rate plan. Try a different range (see example above).

  - Port already in use:
      Something else is on 4000 or 5173. Stop it, or change the
      port (API: PORT in .env;  website: server.port in
      vite.config.js).

  - Images show as striped "PHOTO" placeholders:
      That's expected until real images are uploaded via the admin
      dashboard (http://localhost:4000/admin). The site falls back
      to placeholders automatically.

  - API won't start, Prisma error about the database:
      DATABASE_URL in apps\api\.env is wrong, or PostgreSQL isn't
      running. Confirm you can connect with that string first.

  - Seeded prices look wrong after the new year:
      Rate plans are seeded for the CURRENT year. Re-run
      "npm run seed" and it will shift the dates forward.
